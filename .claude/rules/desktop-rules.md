# Desktop rules — apps/desktop (Tauri 2 + React + Vite)

Read before writing any file in `apps/desktop/`. Pair with the `tauri` skill, which covers
framework mechanics; this file is project law.

## Status: scaffolded, not started

`apps/desktop` is `create-tauri-app`'s React template plus this repo's naming (roadmap
v1.2.0, per `PRODUCT.md`). The Rust side has exactly one example command (`greet`), and the
renderer is the template's `App.tsx`. There is no API client, no state layer, no shared-UI
bridge, no tests.

**Propose, don't improvise silently.** State any convention you had to invent in your report.

## What does NOT apply here

`apps/desktop` is a **Vite SPA**, not Next.js:

| Web-player rule | Status in `apps/desktop` |
|---|---|
| FSD layers | Not used |
| `'use client'` / Server Components | No server component model |
| `app/**/page.tsx` route adapters | No file-based routing at all |
| `ROUTES` from `@/shared/routes` | No router installed yet |
| `@bitrate/ui-react` | Not a dependency today — check before assuming |

Rules that **do** apply: `.claude/rules/typescript.md`,
`.claude/rules/code-principles.md`, and the framework-agnostic parts of
`.claude/rules/react.md`.

## Structure

```
apps/desktop/
  src/                  React renderer (Vite)
    main.tsx  App.tsx
  src-tauri/
    src/lib.rs          #[tauri::command] definitions + Builder wiring
    src/main.rs         thin entrypoint, calls lib::run()
    capabilities/       permission grants per window
    tauri.conf.json     windows, security, build hooks
    gen/schemas/        GENERATED — never hand-edit
```

`src-tauri/gen/` is generated by Tauri. Do not edit it; regenerate by building.

## The Rust/renderer boundary

Commands are declared in `lib.rs` and registered in `invoke_handler`. Registering is a
separate step from declaring — a `#[tauri::command]` missing from `generate_handler!` fails
only at runtime, with "command not found".

Every command gets a **typed renderer wrapper**, beside the code that uses it:

```ts
import { invoke } from '@tauri-apps/api/core'

type GreetInput = { name: string }

export async function greet({ name }: GreetInput): Promise<string> {
  return invoke<string>('greet', { name })
}
```

Never call `invoke('...')` inline in a component. `invoke` is untyped by default, so a bare
call is a silent `any`, and the command name then lives in as many places as it is called.

**Rust `snake_case` parameters arrive as `camelCase` from JS.** A command receiving
`undefined` for every argument is nearly always this.

## Capabilities are security, not configuration

`src-tauri/capabilities/default.json` currently grants `core:default` and `opener:default` to
the `main` window. Every permission you add grants the renderer — and anything that ever
executes in it — real access to the user's machine.

- Add the **narrowest** permission the feature needs; scope filesystem grants with path
  variables (`$AUDIO`, `$APPDATA`), never a bare wildcard.
- `opener:default` is already broader than `opener:allow-open-url`; do not widen further
  without cause.
- **State in your report exactly what you widened and why.** This is reviewed like a CSP
  change.

"Not allowed by ACL" at runtime means a missing permission, not a missing command. Add the
permission; do not swap in a broader plugin to get around it.

## CSP is currently disabled — do not leave it that way

`tauri.conf.json` has `"security": { "csp": null }`, the template default. That means the
renderer has **no Content Security Policy**: any injected script runs with whatever native
capabilities the window holds.

That is tolerable only while this app renders nothing but local template content. **Before
this app loads any remote content, renders any API-supplied string, or ships to a user, a CSP
must be set.** Treat `csp: null` as a known open item, not as the settled configuration, and
never "fix" a loading failure by keeping it null or adding `unsafe-inline`.

## Renderer conventions

React function components, named exports, named React imports, named types in signature
positions, no production `any`. ≤100 logic lines per component file, ≤5 own declared props,
≤2 `useEffect`.

Design values should trace back to the token roles in `packages/ui-react/src/styles/`. No bridge exists yet — propose one
rather than scattering hex literals. API types come from `@bitrate/contracts`.

## Commands

```bash
pnpm --filter @bitrate/desktop dev                 # renderer only (Vite, :1420)
pnpm --filter @bitrate/desktop tauri dev           # full app
pnpm --filter @bitrate/desktop check-types    # tsc --noEmit
cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml
```

This app has a `check-types` script but **no lint and no tests**. `cargo check` covers the
Rust half; if the Rust toolchain is not installed, say so rather than reporting a pass. Signed release
builds and code signing are the user's to run.
