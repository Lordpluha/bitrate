Operators can now export the listener, artist, catalog and moderation lists as CSV. The API gains `GET /admin/users/export.csv`, `GET /admin/artists/export.csv`, `GET /admin/tracks/export.csv` and `GET /admin/moderation/reports/export.csv`, behind the new `users:export`, `artists:export`, `tracks:export` and `reports:export` permissions. None of them joins the built-in MODERATOR template: the files carry email addresses and other personal data, so they are administrator-only until an administrator grants them on `staff/:id` (the template only seeds the role on first boot, and existing moderators gain nothing). Each route takes the same filters and sort as its list, minus pagination, and reuses that list's `where` and ordering with the `id` tie-break, so the file holds exactly the rows the list shows across every page; the catalog without `sort` follows the list's problem-first order. Rows are read in batches of 1000 and streamed, never loaded whole, and the file is capped at 50 000 rows. `X-Export-Truncated: true|false` is sent on every export (true when the cap cut the file short) and the panel tells the operator so; CORS exposes it and `Content-Disposition`. The response is `text/csv; charset=utf-8`, `attachment; filename="<resource>-<UTC timestamp>.csv"`, UTF-8 with a byte order mark so Excel opens it correctly, CRLF line endings and RFC 4180 quoting (cells with a comma, quote, CR or LF are quoted and inner quotes doubled). Dates are ISO 8601 UTC, booleans `true`/`false`, null is an empty cell, and a text cell starting with `=`, `+`, `-`, `@`, tab or CR is prefixed with `'` against spreadsheet formula injection. Every export writes one audit row (`admin-users.export`, `admin-artists.export`, `admin-tracks.export`, `admin-moderation.export`) holding the filter summary, the row count and whether it was truncated; exports are GETs, which the request interceptor does not audit.

Column sets, in order. users: `id, username, email, emailVerifiedAt, twoFactorEnabled, lockedUntil, deletedAt, createdAt`. artists: `id, username, email, verified, monthlyListeners, country, emailVerifiedAt, twoFactorEnabled, deletedAt, createdAt`. tracks: `id, title, artistId, artistUsername, processingStatus, processingError, processingAttempts, processingFinishedAt, deletedAt, createdAt`. reports: `id, status, entityType, entityId, reason, details, reporterId, resolvedAt, createdAt`. Media, free-form profile text, security counters and `updatedAt` are deliberately left out.

The panel adds an Export CSV button to the listeners, artists, catalog and moderation lists, shown only to operators holding the matching export permission. It downloads the server's CSV for the filters and sort in the current URL over the existing cookie-authenticated HTTP layer (a blob download, no token in JavaScript), with an inline error when it fails. No migrations.
