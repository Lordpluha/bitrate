# @bitrate/web-artists

TanStack Start web application for the Bitrate artists portal.

## Stack

- **TanStack Start 1.x** (Vite 8, Nitro), TanStack Router, React 19, TypeScript
- **TailwindCSS v4**, `@bitrate/ui-react` — shared component library
- **`@bitrate/contracts`** — OpenAPI TypeScript types (generated from Swagger)
- **Biome** — lint + format
- **Port:** 3002

Follows **Feature-Sliced Design**:

```
src/
  routes/     — TanStack Router file routes (__root.tsx owns the document)
  router.tsx  — router factory; the Start plugin calls getRouter() per request
  views/      — full-page view compositions
  widgets/    — self-contained page sections
  features/   — user interactions
  entities/   — domain objects
  shared/     — cross-cutting utilities, API client, hooks
```

`src/routeTree.gen.ts` is generated by the router plugin and **committed**, so `tsc --noEmit`
and CI type checks run without a build first. Do not hand-edit it; it is excluded from lint.

## Getting Started

```bash
# From repo root — installs all workspace deps
pnpm install

# Dev server (http://localhost:3002)
pnpm --filter @bitrate/web-artists dev

# Type check
pnpm --filter @bitrate/web-artists check-types

# Build, then run the production server
pnpm --filter @bitrate/web-artists build
pnpm --filter @bitrate/web-artists start
```

Or inside `apps/web-artists/`:

```bash
pnpm dev     # starts ui-react build first via predev hook
pnpm build
pnpm check-types
```

## Environment

The client reads **`VITE_API_URL`**. Vite only exposes `VITE_`-prefixed variables to the
bundle, and it inlines them at **build** time — setting the variable at container runtime does
nothing. The deployment variable is still called `NEXT_PUBLIC_API_URL` because it is shared
with `apps/web-player`; the rename happens at this app's boundary only, in three places:

| Where | Line |
|---|---|
| `Dockerfile` | `ARG VITE_API_URL` in the **build** stage |
| `infra/docker-compose.{preprod,prod}.yaml` | `VITE_API_URL: ${NEXT_PUBLIC_API_URL}` on the `web-artists` service |
| `.github/workflows/{web_artists,security}_reusable.yml` | `VITE_API_URL=` build arg |

Copy `.env.example` to `.env` for local work.

## Authenticated area — not built yet

The portal ships no authenticated routes. Under Next this was an edge `middleware.ts` whose
`PROTECTED_PREFIXES` list was empty, so it never redirected anyone; it was dropped in the
TanStack Start migration rather than ported as dead code.

When the dashboard lands, the guard belongs in a layout route's `beforeLoad`, and it needs
three things the old middleware knew:

- the refresh cookie is httpOnly, so the check runs on the server — read it with `getCookie`
  from `@tanstack/react-start/server`, wrapped in a `createServerFn` so `beforeLoad` can call
  it from either side;
- the cookie name comes from `REFRESH_TOKEN_NAME`, defaulting to `refresh_token`;
- an unauthenticated visitor is redirected to `ROUTES.auth.login` with the path they wanted in
  a `next` search param.

## Notes

- The `predev` hook automatically builds `@bitrate/ui-react` before starting the dev server.
- Requires the API running on port 3000 for data fetching.
- Nitro (`@tanstack/nitro-v2-vite-plugin`) is what makes `pnpm build` emit a runnable
  `.output/server/index.mjs`. Without it, `vite build` emits a fetch handler that exits
  immediately under `node` — there would be nothing to deploy.
