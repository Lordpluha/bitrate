ADR-0020: Single-file CMAF + Range index + MSE for audio playback

Accepted2026-08-116 min read

Context#

The web player streams audio through HLS (hls.js, ~135 storage objects per track, every 4-second segment proxied through NestJS) plus a progressive Opus fallback and a dead WebSocket transport. The HLS cost is paid in full while its only real benefit — adaptive bitrate — is never used.

The decisive question turned out not to be “segments or whole file” but who controls the buffer. With a plain <audio> element the browser owns buffering, and switching quality means re-downloading a second file from the current position.

Note

Three replacement variants were compared in the player variants source diagram before this decision.

Decision#

Encode one fragmented-MP4 (CMAF) file per bitrate, index it by byte range, and drive playback from a first-party MediaSource loader with our own ABR.

Encoding#

convertAudioToCmaf in @bitrate/converter runs FFmpeg once with one output per bitrate, so the source decodes a single time and all renditions share fragment boundaries.

packages/converter/src/cmaf.ts
// 192 AAC frames × 1024 samples / 48 kHz = 4.096 s exactlyconst FRAGMENT_SECONDS = (192 * 1024) / 48_000export async function convertAudioToCmaf(input: string, bitrates: number[]) {  const args = ['-movflags', '+cmaf+global_sidx', '-ar', '48000', '-ac', '2']  return runFfmpeg(input, bitrates.map((kbps) => [...args, `-b:a ${kbps}k`]))}
Warning

+frag_keyframe+empty_moov alone does not write a sidx. Without it the fragment index cannot be built.

Manifest contract#

FieldMeaning
timescaleticks per second, 48000
durationTickstotal track duration
renditions[].initRangeftyp+moov only — sidx is excluded
renditions[].fragments[startTicks, durationTicks, offset, length]
Tip

Byte ranges are inclusive on both ends, matching HTTP Range.

Consequences#

  • Storage objects per track drop from ~135 to one file per rendition.
  • Quality is decided per fragment rather than once at startup.
  • Devices without MSE play the same file through <audio>; only adaptivity is lost.
Danger

Never hardcode initRange: FFmpeg 6.1 emits a 709-byte ftyp+moov while 7.0.2 emits 708 for the same input.
